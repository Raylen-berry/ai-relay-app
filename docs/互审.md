# 执行方式与互审

[返回首页](../README.md) · [文档导航](README.md)

## 三种方式怎么选

| 方式 | 模型会看到什么 | 过程 |
| --- | --- | --- |
| 单次完成 | 模型 1 看任务与资料 | 生成结果，再由工具和你核对 |
| 独立核查 | 模型 2 看原始任务和资料，不看初稿 | 模型 1 对照两份结果定稿 |
| 查看初稿后互审 | 审核者看到待审初稿与任务 | 逐轮检查，再回传模型 1 定稿 |

三项资料流程默认单次完成。需要另一份判断时可选独立核查；需要逐轮检查和修改时使用多轮互审。

## 模型与顺序

网页模型使用当前已登录账号。文字 API 可以作为可选执行方式，配置见 [API](API.md)。

多轮互审支持 3–9 轮，从模型 1 开始，最后回到模型 1。常用顺序如 `1-2-1`、`1-2-1-2-1`，也可用第三个不同的模型。

首次进入各模型会创建本次任务对话；返回时复用原对话和已上传附件。运行中不能通过快捷选择改动正在执行的任务。

展开 **每轮审核分工** 可设检查重点，查看每轮回答与修改说明。最终模型应说明吸收或驳回意见的理由，而不是仅因审核者这样说就采用。

## 核对哪些内容

用途、交付形式和验收条件帮助模型对齐目标；成果生成与人工核对分别记录。引用编号能匹配原文，不等于结论已经成立；多家模型意见相同也不能代替证据。

数字核对和引用检查的具体范围见[流程](流程.md)与[交付](交付.md)。想比较互审是否值得，按[试用](试用.md)使用相同资料与验收条件，记录检查、返工、等待和调用成本。

## 运行上限

可设置自动处理时间、API 发送尝试次数和单次输出 token 上限。当前默认值为 60 分钟、6 次 API 尝试、4096 输出 token；范围分别为 5–480 分钟、1–50 次、256–32768 token。

限制在新的发送前检查，达到后暂停并保留内容；需要继续时由你明确增加额度。单次 API 请求还按剩余等待时间限制超时。

已发出的请求可能继续处理，次数和 token 上限不能直接换算为账单金额。输出被截断或发送状态不明时，不会自动重发或切换服务，按[常见问题](常见.md)处理。
